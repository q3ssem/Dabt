# مختبر التجارب والأبحاث — Research Lab

هذا **مجلد للمطورين داخل المستودع**، وليس شاشة للاعبين أو جزءًا من ملفات التحميل عند نشر التطبيق.

## ترقيم ثابت يمنع ضياع العمل
- **EXP-0001**: أول دراسة للتبعيات.
- **EXP-0002** وما يليها: أي تجربة جديدة، لا يُعاد استخدام رقم مغلق.
- **ADR-0001**: قرارات هندسية ثابتة وقابلة للمراجعة.
- سجل كل تجربة في `REGISTRY.json` بمسارها وحالتها ومسؤوليتها ونتيجة الاختبار.
- أسماء الحالات: `planned`، `in-progress`، `blocked`، `validated`، `rejected`، `archived`.

## إنشاء تجربة جديدة برقم تلقائي
من جذر `mindlab6/`:
```bash
npm run experiment:new -- "تجربة حجم اللمس" touch-targets --dry-run
npm run experiment:new -- "تجربة حجم اللمس" touch-targets
```
ينشئ المولد مجلد `EXP-NNNN-touch-targets` برقم جديد فعلي (EXP-0002 محجوزة بالفعل لاختبار التماثيل) وملفات `code/` و`data/` و`results/` ويسجله في `REGISTRY.json`، ولا يُبدّل التجربة النشطة تلقائيًا. إذا أصبحت التجربة مهمة الجلسة، حدّث `PROJECT_STATE.json` و`handoff/CURRENT_TASK.md` و`handoff/SESSION_LOG.md` صراحة.

## ملفات كل تجربة
أنشئ مجلد `experiments/EXP-NNNN-descriptive-slug/` برقم غير مستخدم وضع فيه:
`README.md` للفرضية وهدف التجربة ونتيجتها؛
`code/` لبرمجيات الاختبار؛
`data/` لمدخلات عامة/صناعية فقط؛
`results/` لمقاييس وتقارير حقيقية مع طريقة إعادة الإنتاج.
ابدأ من `experiments/_TEMPLATE.md`، وحدث الفهرس عند الإنشاء/تغيير الحالة.

## الحماية
- لا يجوز أن تستورد `src/` أي ملف من `research/`.
- لا تنشر سجلات لاعبين حقيقيين أو مفاتيح API أو ملفات خاصة.
- نتائج البحث لا تصبح جزءًا من التطبيق حتى تمر بمراجعة، واختبارات وظيفية، وإقرار ADR عند الحاجة.
- اكتب دائمًا ما **لم** ينجح، وليس النجاحات فقط.
- إن اختلفت الذاكرة مع `handoff/` و`REGISTRY.json` فمصدر الحقيقة هو الملفات على رأس الفرع.
