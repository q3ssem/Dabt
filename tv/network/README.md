# Majlis Network 3.0 — P1
Independent lab, not integrated with Kahoot. One host and one remote per freshly generated invitation. Open network/index.html over HTTPS (or loopback), create invitation, share with trusted remote, join. Do not reuse invitations. Public MQTT is only signalling/experimental fallback; all relay messages (including SDP and motion) are AES-GCM authenticated/encrypted with a random 256-bit invite secret in the URL fragment, not in MQTT topic. Random 128-bit topic; first authenticated peer locks the link. Possession of invite = permission; no protection against a participant sharing invite, malicious broker dropping/delaying traffic, or compromise of page/device. Direct DTLS DataChannel unordered maxRetransmits=0. Local ICE only by default; no cloud provisioned. Optional iceServers passed to API, no credentials embedded. Direct preferred, relay if unavailable or measured p95 worse by 35ms with hysteresis. Ping median/p95, consecutive RTT variation, timed-out probes. Host rejects older movement sequences, neutral watchdog 350ms. Lab sends 10 Hz during hold (not final arcade rate). No retry of obsolete movement on direct channel, no automatic ICE restart in P1; recreate invitation after reload. Multiple simultaneous controllers, ICE restart, bounded relay queue, reliable action channel, private managed signalling, TURN credentials and TV device QA are next gates. No changes to Kahoot app, cache, main app or dev2; lab not in cache yet. Tests use local synthetic relay, not public broker or Saudi home network. No stress testing.
