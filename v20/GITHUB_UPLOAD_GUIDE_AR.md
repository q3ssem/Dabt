# رفع V20 إلى GitHub بأمان (فرع تجريبي)

لا ترفع هذه النسخة فوق `main` مباشرة. ارفعها أولاً على فرع مستقل باسم `v20-test` حتى تبقى النسخة الحالية كما هي.

## باستخدام GitHub Desktop (الطريقة الأسهل)

1. نزّل مستودع `q3ssem/Dabt` إلى الكمبيوتر وافتحه في GitHub Desktop.
2. من قائمة **Branch** اختر **New Branch** واكتب `v20-test` واجعله مبنياً على `main`.
3. فك ضغط حزمة V20.
4. افتح المجلد الداخلي `Dabt_PRO_V18_0` وانسخ **محتوياته** إلى مجلد المستودع المحلي، وليس المجلد الخارجي نفسه. وافق على استبدال الملفات المتطابقة.
5. لا تحذف ملفات المستودع الموجودة إلا إذا كان الاستبدال جزءاً واضحاً من هذه النسخة. راجع قائمة التغييرات قبل المتابعة.
6. في GitHub Desktop اكتب رسالة مثل `Add Dabt PRO V20 test preview` ثم اختر **Commit to v20-test** وبعدها **Push origin**.
7. افتح GitHub وتأكد أن الملفات ظهرت في فرع `v20-test`. أنشئ Pull Request إلى `main` للمراجعة فقط؛ لا تدمجه حتى تنتهي تجربة الكمبيوتر والجوال.

## النشر على GitHub Pages

رفع الفرع لا يغيّر الموقع المنشور تلقائياً. بعد مراجعة V20، يمكن اختيار فرع النشر من **Settings → Pages**. لا تغيّر إعداد Pages من `main` إلى `v20-test` إلا إذا كنت تقصد أن يصبح هذا الفرع هو الموقع العام.

## قبل الدمج إلى main

- تأكد من فتح الصفحة الرئيسية عبر HTTPS.
- اختبر التنقل والألعاب وحفظ التقدم والنسخ الاحتياطي على Safari وChrome.
- اختبر «إضافة إلى الشاشة الرئيسية» على iPhone.
- شغّل `npm test` من `engine-phaser` بعد تثبيت الاعتماديات.
- لا تدمج Pull Request إذا ظهرت أخطاء أو كانت تجربة الأجهزة غير مكتملة.

لا تضع رموز وصول GitHub أو كلمات المرور داخل ملفات المشروع أو المحادثة.
